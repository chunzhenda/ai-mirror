# 小智 (XiaoZhi) 语音助手 — 项目分析文档

> 生成日期: 2026-07-12
> 硬件: ESP32-S3 + ES8311 + GC9A01 (240×240 圆屏)

---

## 一、当前项目 vs 小智 — 差别分析

| 模块 | 当前项目状态 | 小智目标状态 | 差距等级 |
|------|-------------|-------------|---------|
| **音频采集** | ✅ I2S + ES8311 已调通，16kHz/16bit 录音 | 需要增加 VAD (语音活动检测)，自动检测说话结束 | 🟡 中等 |
| **音频播放** | ✅ I2S TX 通道 + ES8311 喇叭输出正常 | 需要 TTS 音频流播放 + 音量控制 | 🟢 简单 |
| **LCD 显示** | ✅ GC9A01 裸机驱动，`esp_lcd_panel_draw_bitmap` 直接刷图 | 需要增加 UI 框架：状态栏、表情动画、对话文字、设置页 | 🟡 中等 |
| **触摸/按键** | ✅ GPIO 按键驱动已写（去抖、长短按） | 触摸屏需 I2C 驱动（可选），按键已够用 | 🟢 简单 |
| **WiFi** | ❌ 已删除（之前版本有），当前无网络功能 | 必须：STA 模式 + 自动重连 | 🔴 必须 |
| **云端通信** | ❌ 已删除 | 必须：WebSocket / HTTP 与 AI 服务通信 | 🔴 必须 |
| **语音识别 (ASR)** | ❌ 无 | 音频编码 → 发送云端 → 接收文字 | 🔴 必须 |
| **AI 对话 (LLM)** | ❌ 无 | 接收文字 → 发送 LLM → 接收回复 | 🔴 必须 |
| **语音合成 (TTS)** | ❌ 无 | 接收 AI 文字 → 获取音频 → 播放 | 🔴 必须 |
| **VAD 静音检测** | ❌ 无 | 能量阈值检测，自动结束录音 | 🟡 中等 |
| **音频编码** | ❌ 无 (当前原始 PCM) | 可选用 Opus/AMR 压缩减少带宽 | 🟢 可选 |
| **表情系统** | 仅有 4 帧静态眼图 | 动态表情切换：听/想/说/待机/错误 | 🟡 中等 |
| **内存管理** | 无优化 | 需要 PSRAM 利用、环形缓冲、内存池 | 🟡 中等 |
| **错误处理** | 简单 abort | 优雅降级、重连机制、错误状态显示 | 🟡 中等 |

## 六、云端协议参考

```json
// 客户端 → 服务器
{"type":"hello", "sample_rate":16000, "channels":1, "format":"pcm"}
{"type":"sos"}                              // 开始说话
<binary PCM audio>                          // 实时音频数据
{"type":"eos"}                              // 结束说话

// 服务器 → 客户端
{"type":"hello_ack", "session_id":"xxx"}
{"type":"stt", "text":"用户说了什么"}         // 语音识别结果
{"type":"llm", "text":"AI 的回复"}           // AI 对话结果
{"type":"tts", "audio":"<base64 PCM>"}      // TTS 音频 (可改为 hex/raw)
{"type":"emotion", "value":"happy"}          // 表情指令
{"type":"error", "message":"xxx"}            // 错误信息
```
